01 Arquitectura y Principios de Diseño

JumpServer Kiosk Manager es una solución desarrollada para orquestar consolas web aisladas en JumpServer Community Edition (CE) sin requerir la suscripción Enterprise comercial ni módulos privativos.

⚡ Just-In-Time (JIT)

0% CPU y 0 MB RAM en reposo. Los contenedores se encienden al recibir el paquete RDP-SYN y se apagan automáticamente al terminar la sesión.

🛡️ JumpServer v4 RBAC

Firmas criptográficas HMAC-SHA256 por petición y compatibilidad nativa con el modelo de permisos y roles de JumpServer v4.

🔒 Hardening Dinámico

Chromium restringido vía políticas corporativas: DevTools desactivadas (F12), descargas bloqueadas y aislamiento estricto de esquemas file:// o chrome://.

💾 Persistencia Aislada

Volúmenes Docker dedicados preservan contraseñas y cookies del operador, aplicando límites de caché estrictos para evitar fugas de almacenamiento.

Flujo de Conexión y Topología de Componentes

El sistema distribuye sus responsabilidades entre el plano de control (API FastAPI en host network), la interfaz gráfica (Nginx en puerto 8080) y el Dispatcher TCP que monitorea el rango de puertos 33891 - 34090:

Diagrama Conceptual de Flujo
ASCII Topo 
[ OPERADOR (Navegador) ] 
       │ HTTP/WS (:80)
       ▼
[ JUMPSERVER v4.10.x CE ]
  ├─ jms_core (API REST HMAC-SHA256) ──► Kiosk Manager Backend (:8000 / host)
  └─ jms_lion (Guacamole RDP Proxy)   ──► RDP Dispatcher Pool (:33891 - :34090 / host)
                                                │ (Detección RDP-SYN / Docker Socket)
                                                ▼
                                      [ pam-web-kiosk (JIT Container) ]
                                      - XRDP Interno (:3389 / Bridge 172.17.0.x)
                                      - Openbox + Chromium Kiosk Restringido
                                      - Volumen Persistente (Login Data / Cookies)
                                                │
                                                ▼ HTTP / HTTPS
                                      [ DISPOSITIVO WEB DESTINO ]
                                      (Switch, Router, Firewall, Zabbix, iDRAC)
Protección estricta de recursos: El Dispatcher gestiona cuatro políticas concurrentes de conservación de recursos:
  • Ventana de gracia tras desconexión (30s): Tolera recargas con F5 o cortes breves de red antes de apagar el contenedor.
  • Inactividad de tráfico (15 min): Corta la sesión si no hay tráfico RDP activo.
  • Límite continuo absoluto (4 horas): Detiene sesiones huérfanas de forma improrrogable.
  • Límite de concurrencia máxima (4 sesiones por defecto): Rechaza preventivamente nuevas conexiones si se alcanza la cuota de RAM del host.

02 Matriz de Puertos y Reglas de Firewall

Para garantizar una comunicación sin interrupciones entre los componentes de JumpServer, los operadores y el Kiosk Manager, configure los siguientes puertos en el firewall (UFW / iptables / Security Groups):

Puerto Protocolo Origen Destino Función / Componente
80/tcp, 443/tcp HTTP / HTTPS Operadores / Red LAN Host JumpServer Portal Web JumpServer Luna y autenticación principal
2222/tcp SSH Operadores Host JumpServer (koko) Terminal CLI JumpServer Koko (SSH Proxy)
8080/tcp HTTP Administradores Kiosk Manager (Nginx) Dashboard Web de administración de quioscos
8000/tcp HTTP Localhost / Docker Backend FastAPI API REST interna (reverso-proxyficada por Nginx :8080)
33891 - 34090 TCP Host (jms_lion) RDP Dispatcher Pool Escucha dinámica de sesiones RDP para quioscos efímeros
3389/tcp RDP Dispatcher (Host) Contenedor Efímero Interno a la red Docker bridge (no exponer en el host)

Reglas de Firewall Recomendadas (UFW)

Configuración UFW en el Host
# Permitir acceso al portal JumpServer y SSH administrativo
sudo ufw allow 22/tcp comment 'SSH Host'
sudo ufw allow 80/tcp comment 'JumpServer HTTP Web'
sudo ufw allow 443/tcp comment 'JumpServer HTTPS Web'
sudo ufw allow 2222/tcp comment 'JumpServer Koko CLI'

# Permitir acceso al Dashboard del Kiosk Manager (solo administradores)
sudo ufw allow 8080/tcp comment 'Kiosk Manager Web Dashboard'

# Los puertos 33891:34090 comunican jms_lion con el dispatcher en localhost o LAN
sudo ufw allow 33891:34090/tcp comment 'Kiosk Dispatcher RDP Relay Pool'

# Habilitar firewall
sudo ufw enable
sudo ufw status verbose

03 Escenario A: Servidor Ubuntu 24.04 Limpio (Greenfield)

Siga esta guía si está configurando un nuevo servidor físico, máquina virtual (KVM/Proxmox VE) o instancia cloud desde cero para albergar tanto JumpServer v4 como JumpServer Kiosk Manager.

1

Actualización del Sistema y Paquetes Esenciales

Instale las utilidades base requeridas para la orquestación, gestión de red, SQLite y cron:

Terminal Bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y curl wget git jq sqlite3 cron ca-certificates gnupg lsb-release tar gzip ufw

# Asegurar que el servicio cron esté activo y habilitado en el arranque
sudo systemctl enable --now cron
2

Instalación Oficial de Docker Engine y Docker Compose

Configure el repositorio oficial de Docker para Ubuntu e instale el motor de contenedores:

Repositorio Oficial Docker
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# Iniciar y comprobar Docker
sudo systemctl enable --now docker
docker --version && docker compose version
3

Instalación de JumpServer Community Edition v4

Descargue e instale JumpServer v4.10.x CE utilizando el instalador oficial:

Instalador Oficial JumpServer
# Descarga del script de despliegue rápido oficial de JumpServer
curl -sSL https://resource.fit2cloud.com/jumpserver/jumpserver/releases/latest/download/quick_start.sh | bash

# O alternativamente con release específico v4.10.x:
cd /opt
# Siga el asistente interactivo aceptando las opciones por defecto (puerto 80, MySQL nativo o embedded)

# Verificar que todos los servicios estén en ejecución:
./jmsctl.sh status
Inicie sesión en JumpServer Web (http://<IP-SERVIDOR>) con el usuario inicial admin / admin, cambie la contraseña y confirme que puede acceder a la interfaz Luna.
4

Despliegue de JumpServer Kiosk Manager

Cree el directorio /opt/jumpsrv y descargue los archivos del stack:

Clonación y Configuración
sudo mkdir -p /opt/jumpsrv /backup/kiosk_db
cd /opt/jumpsrv

# Clonar repositorio
sudo git clone https://github.com/larentimatias7-oss/jumpsrv.git .
sudo cp .env.example .env

# Dar permisos de ejecución a los scripts
sudo chmod +x scripts/backup_database.sh scripts/backup.sh scripts/kioskctl

Ajuste las variables en .env según su entorno:

Configuración .env
# URL local de JumpServer
JMS_BASE_URL=http://127.0.0.1:80

# Dejar JMS_KEY_ID y JMS_SECRET_KEY vacíos para autodescubrimiento automático vía jms_core
JMS_KEY_ID=
JMS_SECRET_KEY=

# Organización por defecto JumpServer v4 (System Org)
JMS_ORG_ID=00000000-0000-0000-0000-000000000002

# IP LAN del host visible para JumpServer Lion (si se deja vacío, se auto-detecta)
KIOSK_HOST_IP=

# Credenciales para el Dashboard Web (:8080)
PORTAL_ADMIN_USER=admin
PORTAL_ADMIN_PASSWORD=ContraseñaSegura2026!
SECRET_KEY=$(openssl rand -hex 32)

# Políticas de memoria RAM y concurrencia
KIOSK_DISCONNECT_GRACE_SECONDS=30
KIOSK_IDLE_TIMEOUT_SECONDS=900
KIOSK_MAX_SESSION_LIFETIME_SECONDS=14400
KIOSK_MAX_CONCURRENT_SESSIONS=4

Levante los contenedores en producción:

Iniciar Stack de Producción
# Iniciar servicios en segundo plano
sudo docker compose -f docker-compose.prod.yml up -d

# Inspeccionar logs del backend y verificar autodescubrimiento de AccessKey
sudo docker compose -f docker-compose.prod.yml logs -f backend
5

Programación del Respaldo SQLite en Crontab

Configure la tarea automática para realizar copias en caliente consistentes de la base de datos WAL:

Configuración de Cron (Host)
# Prueba manual del script
sudo /opt/jumpsrv/scripts/backup_database.sh /var/lib/docker/volumes/jumpsrv_kiosk_db_data/_data/kiosk.db /backup/kiosk_db 7

# Añadir a crontab para ejecución a las 03:00 AM diaria
(sudo crontab -l 2>/dev/null; echo "0 3 * * * /opt/jumpsrv/scripts/backup_database.sh /var/lib/docker/volumes/jumpsrv_kiosk_db_data/_data/kiosk.db /backup/kiosk_db 7 >> /var/log/kiosk_backup.log 2>&1") | sudo crontab -

04 Escenario B: Servidor con JumpServer v4 en Ejecución

Este escenario es el más común en entornos corporativos donde JumpServer v4 ya se encuentra operando y administrando servidores SSH, RDP y bases de datos. Kiosk Manager se añade de forma completamente no invasiva.

Garantía de No Invasión: Kiosk Manager no modifica ningún contenedor existente de JumpServer, no altera la base de datos MySQL de JumpServer y no requiere reiniciar el servicio principal de JumpServer.
1

Auditoría de Salud del Stack JumpServer Existente

Compruebe que JumpServer v4 esté funcionando y que los contenedores jms_core y jms_lion estén saludables:

Verificación de Estado
# Comprobar estado de JumpServer
cd /opt/jumpserver-installer-* 2>/dev/null || cd /opt/jumpserver
./jmsctl.sh status

# Verificar que el socket Docker del host esté disponible
ls -la /var/run/docker.sock

# Comprobar presencia de paquetes mínimos
which sqlite3 || sudo apt update && sudo apt install -y sqlite3 cron
2

Despliegue Paralelo en /opt/jumpsrv

Despliegue el stack de Kiosk Manager sin colisionar con rutas de JumpServer:

Despliegue Paralelo
sudo mkdir -p /opt/jumpsrv /backup/kiosk_db
cd /opt/jumpsrv
sudo git clone https://github.com/larentimatias7-oss/jumpsrv.git .
sudo cp .env.example .env
sudo chmod +x scripts/*.sh

# Generar clave secreta para la sesión
sed -i "s/SECRET_KEY=.*/SECRET_KEY=$(openssl rand -hex 32)/" .env

# Levantar Kiosk Manager
sudo docker compose -f docker-compose.prod.yml up -d
3

Verificación del Autodescubrimiento Cero-Configuración

El backend se conecta con jms_core y resuelve el AccessKey con permisos de Administrador vía RBAC:

Inspección de Logs de Autodescubrimiento
sudo docker compose -f docker-compose.prod.yml logs backend | grep -i "autodiscover"

Deberá observar una salida exitosa similar a:

[INFO] autodiscover: Discovered active JumpServer core container: jms_core
[INFO] autodiscover: Retrieved administrative AccessKey ID: 3e8f...
[INFO] autodiscover: Cached credentials safely in /app/data/jms_credentials.json

05 Respaldos Automatizados SQLite (WAL) y Cron

La base de datos de metadatos de quioscos utiliza SQLite en modo WAL (Write-Ahead Logging). Copiar el archivo directamente con cp puede provocar inconsistencias o estados corruptos si hay transacciones concurrentes en vuelo.

Mecanismo de Respaldo Seguro: scripts/backup_database.sh

El script oficial incluido en el repositorio utiliza la API en línea de SQLite:

  • Invoca el comando nativo sqlite3 "$DB" ".backup '$BACKUP_FILE'" (con fallback automático a la API sqlite3.backup de Python si la CLI no estuviera instalada).
  • Realiza una comprobación estricta de integridad tras la copia: PRAGMA integrity_check;.
  • Calcula el tamaño del respaldo y purga automáticamente cualquier copia con más de 7 días de antigüedad (-mtime +7 -delete).
Verificación del Script
# Comprobar permisos del script
ls -la /opt/jumpsrv/scripts/backup_database.sh

# Ejecutar respaldo manual
sudo /opt/jumpsrv/scripts/backup_database.sh /var/lib/docker/volumes/jumpsrv_kiosk_db_data/_data/kiosk.db /backup/kiosk_db 7

# Listar respaldos generados
ls -lh /backup/kiosk_db/

Procedimiento de Restauración

Si requiere restaurar la base de datos ante una contingencia:

Restauración Paso a Paso
# 1. Detener el backend de Kiosk Manager
cd /opt/jumpsrv
sudo docker compose -f docker-compose.prod.yml stop backend

# 2. Reemplazar la base de datos activa por el respaldo elegido
TARGET_DB="/var/lib/docker/volumes/jumpsrv_kiosk_db_data/_data/kiosk.db"
BACKUP_TO_RESTORE="/backup/kiosk_db/kiosk_20260913_030000.db"

sudo cp "$BACKUP_TO_RESTORE" "$TARGET_DB"
# Eliminar archivos journal / wal residuales
sudo rm -f "${TARGET_DB}-wal" "${TARGET_DB}-shm"

# 3. Reiniciar el backend
sudo docker compose -f docker-compose.prod.yml start backend
sudo docker compose -f docker-compose.prod.yml logs backend

06 Verificación Post-Instalación y Suite E2E

Valide que el aprovisionamiento, la creación de activos en JumpServer v4 y el despacho RDP funcionen de extremo a extremo:

1

Ejecución de la Suite de Pruebas E2E (8 Fases)

El repositorio incluye una suite automatizada completa que prueba todas las etapas:

Suite E2E Automatizada
cd /opt/jumpsrv
python3 scripts/e2e_test_runner.py

La suite valida:

  1. Salud y respuesta de la API FastAPI (/health).
  2. Autodescubrimiento y validación de AccessKey con JumpServer v4.
  3. Aprovisionamiento transaccional de un quiosco de prueba.
  4. Verificación del activo registrado en JumpServer (/api/v1/assets/hosts/).
  5. Apertura del puerto RDP en el Dispatcher y simulación de conexión.
  6. Arranque del contenedor efímero y respuesta de XRDP.
  7. Apagado por ciclo de vida y transición de estado a IDLE.
  8. Rollback limpio y eliminación del activo de prueba.
2

Prueba Operativa desde la Interfaz Web

  1. Abra en su navegador http://<IP-SERVIDOR>:8080 e ingrese con las credenciales configuradas en .env.
  2. Haga clic en + Nuevo Quiosco, ingrese un nombre (ej. Firewall-Edge), la URL de destino (ej. https://192.168.1.1) y guarde.
  3. Verifique que el quiosco aparezca en estado IDLE (En espera).
  4. Haga clic en el botón Luna para abrir JumpServer Web Terminal.
  5. Conéctese al activo: observe cómo el estado cambia instantáneamente a RUNNING y Chromium carga la consola del dispositivo.
  6. Cierre la pestaña de Luna: verifique en los logs del backend que tras la ventana de gracia (30s) el contenedor se apaga y vuelve a IDLE.

07 Operación, Mantenimiento y Troubleshooting

Comandos de Operación Frecuentes

Comandos CLI de Mantenimiento
# Ver estado de los contenedores del stack
sudo docker compose -f /opt/jumpsrv/docker-compose.prod.yml ps

# Ver contenedores de quiosco activos o detenidos
sudo docker ps -a --filter label=managed-by=jumpserver-kiosk-manager

# Seguir logs del backend y Dispatcher en tiempo real
sudo docker compose -f /opt/jumpsrv/docker-compose.prod.yml logs -f --tail=100 backend

# Actualizar las imágenes Docker del stack a la última versión
cd /opt/jumpsrv
sudo docker compose -f docker-compose.prod.yml pull
sudo docker compose -f docker-compose.prod.yml up -d

# Limpiar todos los contenedores efímeros detenidos (los volúmenes se conservan intactos)
sudo docker rm -f $(sudo docker ps -aq --filter label=managed-by=jumpserver-kiosk-manager)

Resolución de Problemas Frecuentes (Troubleshooting)

1. Error de permisos en el socket Docker (Permission Denied)

Síntoma: El log del backend muestra PermissionError: [Errno 13] Permission denied: '/var/run/docker.sock'.

Solución: Asegúrese de que el socket del host tenga permisos de lectura y escritura para el contenedor:

Ajuste de Permisos de Socket
sudo chmod 666 /var/run/docker.sock
# O agregue el usuario del contenedor al grupo docker

2. Puerto ocupado o conflicto en rango de Dispatcher (Address already in use)

Síntoma: Fallo al iniciar la escucha en el puerto 33891.

Diagnóstico y Solución: Identifique qué proceso está utilizando el puerto:

Identificación de Procesos en Conflicto
sudo ss -tulpn | grep 33891
# Si es un proceso antiguo huérfano, finalícelo:
sudo fuser -k 33891/tcp

3. Error de firma HMAC en JumpServer v4 (Diferencia de Reloj / NTP)

Síntoma: 401 Unauthorized - Signature check failed en las llamadas hacia /api/v1/....

Causa: La especificación de firma HMAC de JumpServer rechaza peticiones con desincronización de reloj superior a 15 minutos.

Solución: Sincronice el reloj del servidor mediante chrony o systemd-timesyncd:

Sincronización NTP
sudo timedatectl set-ntp true
sudo timedatectl status

4. Paquetes cron o sqlite3 no encontrados en Ubuntu Minimal

Síntoma: Errores crontab: command not found o sqlite3: command not found durante el backup.

Solución: Instale ambos componentes:

Instalación en Ubuntu Minimal
sudo apt update && sudo apt install -y sqlite3 cron
sudo systemctl enable --now cron
